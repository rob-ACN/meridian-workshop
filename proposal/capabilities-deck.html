Codebase review

What the previous vendor left

We reviewed the handoff documentation and codebase. The stack is sound — Vue 3 + FastAPI is a reasonable foundation. The issues are in execution:

Risk

No tests

No unit, integration, or browser tests delivered. Changes to the codebase are effectively unverifiable.

Incomplete

Mixed patterns

Some views use Vue Options API, others Composition API. Migration was started but not finished.

Thin

Minimal docs

Handoff notes cover the stack and API endpoints but leave architecture, data flows, and decisions undocumented.

Our read: the foundation is salvageable. The debt is concentrated, not systemic. We can fix this without a rewrite.

Every new feature we add will stand on a tested, documented foundation — not the fragile base the previous vendor left.

Technical approach

Requirement by requirement

R1 — Reports

Full audit and remediation

We'll systematically reproduce all 8+ logged defects, trace each to its root cause, and fix. Filter wiring, i18n gaps, and data inconsistencies addressed in Phase 1.

R2 — Restocking

New view: purchase recommendations

Stock levels + demand forecast + operator budget ceiling = ranked restock recommendations. Built in Phase 3 on a stable, tested platform.

R3 — Testing

Browser test suite (Playwright)

End-to-end coverage for Inventory, Orders, Reports, and Restocking flows. Tests run in CI so IT can approve changes with confidence.

R4 — Architecture

Current-state documentation

A written + visual architecture overview delivered before new code is added — so Meridian IT owns a clear picture of their system.

Proposal assumptions

What we've assumed

  • A
    UI direction: No formal design system — we'll propose a clean, modern aesthetic incorporating Meridian's brand colors and font.
  • B
    Test scope: All four critical flows — Inventory, Orders, Reports, and Restocking.
  • C
    i18n: Japanese is the primary target; architecture will support additional APAC languages as a follow-on.
  • D
    Environment: Meridian provides access to the current hosting environment and a staging instance for test automation.

These assumptions will be confirmed at project kickoff. Material changes to scope will be discussed before any cost impact is incurred.
