Options API · Defects

Reports.vue

Quarterly/monthly performance. Hardcoded $, no filters, 15+ console.log, wrong API pattern.

Composables

useFilters.js

Singleton shared filter state. Provides getCurrentFilters(), resetFilters(), hasActiveFilters. Used by all views except Reports.

Composables

useI18n.js

English / Japanese locale toggle. Auto-maps currency: en → USD, ja → JPY. Locale persisted in localStorage. Not used by Reports.vue.

Known Debt — Remediation Backlog

High

Reports.vue — no filter integration

Quarterly and monthly data always returns all records regardless of active filters. Other views respect warehouse / category / period / status selection.

High

Reports.vue — hardcoded currency ($)

All monetary values use literal "$". Switching locale to Japanese (JPY) has no effect. useI18n() and formatCurrency() are available but unused.

High

Reports.vue — Options API (inconsistent pattern)

Only view using Options API. All other views use Composition API with <script setup>. Blocks standard composable usage.

Med

Reports.vue — 15+ console.log() statements

Debug output left in production code. Creates noise in browser console and exposes internal data structures.

Med

Missing PurchaseOrderModal component

Dashboard.vue references <PurchaseOrderModal> but the component file does not exist. Backend endpoint is fully implemented.

Low

Hardcoded KPIs in Dashboard.vue

Inventory turnover (4.2), order fill rate (96.8%), processing time (2.8), revenue goal are hardcoded constants — not derived from data.

Low

Tasks not persisted

Task CRUD works in memory but changes are lost on server restart. No write-back to tasks.json.
